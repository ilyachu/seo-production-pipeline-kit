# SEO Production Pipeline

Переносимый набор из 18 SEO-агентов. Каждый агент работает отдельно. Оркестратор соединяет технический аудит, данные спроса, исследование, текст, медиа, проверку, публикацию и наблюдение через проверяемый пакет статьи.

Репозиторий содержит универсальный код, шаблоны и искусственные примеры. Адреса рабочих сайтов, сырые отчёты, учётные данные, скриншоты продакшена и истории выкладки сюда не входят. Результаты каждого запуска хранятся в его рабочем каталоге вне Git.

## Состав

| Путь | Назначение |
|---|---|
| `skills/` | 18 независимых агентов, включая технический аудит, Wordstat, панели владельца, редактуру, два издателя и мониторинг |
| `contracts/` | Схемы артефактов и правила переходов между этапами |
| `tools/technical_audit.py` | Ограниченный обход публичного HTTPS-сайта; панельные данные явно остаются `not_checked` |
| `tools/owner_data.py` | Read-only срез Метрики, Вебмастера и Search Console с проверкой счётчика/свойства |
| `scripts/wordstat_client.py` | Wordstat Cloud; ключ и folder ID находятся вне Git |
| `tools/render_svg_cover.py` | Локальная типографическая SVG-обложка; иллюстрации Codex Image поддерживает `seo-image-producer` |
| `integrations/wordpress-next/` | Отдельный шаблон Next.js App Router + headless WordPress, preflight и создание черновика |
| `integrations/custom-site/` | Контракт для адаптера собственного сайта: draft, read-back, publish, rollback |
| `knowledge/checklist/` | 14 разделов методики SEO-аудита |
| `examples/` | Искусственный пакет статьи и нейтральная SVG-обложка |

WordPress-шаблон можно использовать отдельно: [seo-blog-starter](https://github.com/ilyachu/seo-blog-starter). Для полного SEO-процесса нужен этот репозиторий. Тесты WordPress-шаблона проверяют код локально; публикацию на целевом сайте проверяют отдельно.

## Проверка после клонирования

```bash
python3 scripts/validate_skills.py
python3 -m unittest discover -s tests -q
node integrations/wordpress-next/scripts/validate-template.mjs
node --test integrations/wordpress-next/tests/*.test.mjs
```

`scripts/install.sh` копирует skills в Codex или Claude Code. Сначала посмотрите план без записи:

```bash
./scripts/install.sh --target codex --dry-run
./scripts/install.sh --target claude --dry-run
```

## Запуск одного агента

Откройте `skills/<имя>/SKILL.md` и раздел «Самостоятельный режим». Например:

> Используй `seo-wordstat-collector`. Фраза и регион ниже. Проверь доступ к Wordstat. Если Cloud-ключа нет, объясни, как его получить, или прими ручной CSV. Запиши статус источника, дату и тип частотности. Числа не выдумывай.

Для Wordstat нужны фраза, регион, бизнес-цель и `folder_id` с путём к ключу Yandex Cloud либо CSV. Для Метрики, Вебмастера и GSC нужны точные идентификаторы доступных свойств и read-only OAuth-токены. Полный порядок выдачи прав — в [CREDENTIALS.md](CREDENTIALS.md). Значения токенов не передают в чат и не коммитят.

## Полный конвейер

> Используй `seo-pipeline-orchestrator`. Сайт `https://example.com`, регион и бизнес-цель я передам отдельно. Начни с публичного технического аудита, спроси недостающие доступы, собери реальные запросы и интент, подготовь факты, план, текст, медиа и редакционную проверку. Выбери `wordpress` или `custom-site`. До записи покажи пакет и preview. После подтверждения конкретного черновика сохрани живой URL и повторные проверки.

Запуск по умолчанию ограничен чтением и подготовкой. Издатель сначала создаёт черновик. Публичная публикация требует отдельного решения по конкретной записи. Каждый неизвестный источник получает `not_checked` с причиной; код и тесты сами по себе не доказывают работу на целевом сайте.
