# 2. Техническое SEO

> **[📋 Назад к чек-листу](../README.md)**

---

## 🎯 Почему это важно

Скорость загрузки, мобильная адаптация и безопасность напрямую влияют на ранжирование. Google использует Core Web Vitals как официальный фактор ранжирования (Page Experience), Яндекс также учитывает качество мобильной версии и HTTPS. Технические проблемы могут обесценить идеальный контент: если страница грузится 8 секунд или нечитаема на телефоне, пользователь уходит, а поисковик это фиксирует и понижает позиции. Кроме того, технический аудит — это фундамент: пока он не сделан, нет смысла вкладываться в контент и ссылки.

---

## ✅ Что проверять

- [ ] **Core Web Vitals в зелёной зоне** — LCP (основной контент) до 2,5 с, INP (отклик на взаимодействие) до 200 мс, CLS (визуальная стабильность) до 0,1. Проверять нужно по полевым данным (CrUX), а не только лабораторным.
- [ ] **Мобильная версия работает корректно** — без горизонтального скролла, мелкого немасштабируемого текста, неудобных для пальца кнопок. Проверь на реальном телефоне, а не только в эмуляторе.
- [ ] **HTTPS на всех страницах** — валидный SSL-сертификат, нет просрочки, нет смешанного контента (mixed content: http-ссылки на скрипты, стили, изображения внутри https-страницы).
- [ ] **JS-рендеринг не скрывает основной контент** — текст, ссылки и мета-теги должны быть видны в исходном коде или корректно рендериться серверным рендерингом (SSR/SSG). Проверь «Просмотр страницы» в Search Console.
- [ ] **Изображения оптимизированы** — сжатие без видимой потери качества, форматы WebP или AVIF, атрибуты `width`/`height` для предотвращения CLS, lazy loading для контента ниже первого экрана.
- [ ] **Нет 404 и 500 ошибок на живых страницах** — все страницы из sitemap, каталога и навигации отдают 200. Битые внутренние ссылки исправлены.
- [ ] **Нет мусорных URL-параметров** — `?utm_referrer=`, `?session_id=`, `?click_id=` и прочие служебные параметры не плодят дубли в индексе.
- [ ] **Редиректы не образуют цепочки** — нет A → B → C → D. Каждый лишний редирект добавляет задержку и теряет ссылочный вес.
- [ ] **Структурированные данные (schema.org) валидны** — проверь через валидатор Google Structured Data Testing Tool или Rich Results Test. Битые schema не помогают, а создают шум.

## 🔧 Как проверить вручную

1. **PageSpeed Insights** — вбей URL, смотри вкладку «Core Web Vitals Assessment». Зелёный — хорошо, жёлтый/красный — есть над чем работать. Листай ниже до секции «Diagnostics» — там конкретные рекомендации (сжать изображения, убрать блокирующие скрипты).

2. **Lighthouse в Chrome DevTools** — F12 → Lighthouse → Generate report. Смотри разделы Performance, Accessibility, Best Practices, SEO. Особое внимание на метрики LCP (самый большой элемент), TBT (total blocking time), CLS (сдвиги макета).

3. **Яндекс.Вебмастер** → Диагностика → Мобильная версия. Показывает страницы, где мобильная версия отличается от десктопной, или где есть проблемы с отображением на мобильных. Это прямой сигнал Яндексу.

4. **Проверка HTTPS и mixed content** — открой любую страницу в Chrome, F12 → Console, ищи предупреждения «Mixed Content». Либо пройди краулером (Screaming Frog) с галочкой «Check Mixed Content».

5. **Проверка JS-рендеринга** — Search Console → URL Inspection → View Crawled Page. Сравни скриншот и HTML, который видит Google, с тем, что видишь ты в браузере. Если контент отличается — проблема с рендерингом.

6. **Краулер по всему сайту** — Screaming Frog или Sitebulb. Смотри коды ответа (всё что не 200 — кандидат на исправление), canonical-цепочки, редирект-цепочки. Фильтруй по типу контента (HTML) и смотри только индексируемые страницы.

7. **Платформенная специфика** — На Tilda часто встречаются дубли из-за того, что одна страница доступна по `/page` и `/page/`. На WordPress проверь настройки постоянных ссылок и SEO-плагин. На 1C-Битрикс — проверь, не плодит ли компонент каталога технические дубли с разными sort-параметрами.

## ⚡ Типичные ошибки

- **Шрифты и иконки не загружаются по HTTPS** — сайт на HTTPS, а Google Fonts или Font Awesome подключены по HTTP. Браузер блокирует запрос, вёрстка ломается, пользователь видит «кривой» сайт.
- **Мобильная версия отличается от десктопной по контенту** — например, на мобильной спрятаны цены, описания, отзывы. Поисковик индексирует мобильную версию (Mobile-First Indexing), и если контента там меньше — позиции падают.
- **CLS сдвигает страницу при загрузке** — картинка без размеров, баннер, всплывающая форма или динамический шрифт сдвигают макет, когда пользователь уже начал читать. PageSpeed покажет конкретные элементы с high CLS.
