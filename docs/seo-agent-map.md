## Результат

```callout ok Что входит
18 отдельных агентов, общий контракт и два пути публикации. Каждый этап сохраняет входные данные, результат и статус проверки.
```

## Полный путь

```flow LR
(Сайт и цель) -> Техаудит: HTTP и HTML
Техаудит -> Данные: Wordstat и панели
Данные -> Интент: запрос к странице
Интент -> Исследование: факты с URL
Исследование -> Статья: план, текст, обложка
Статья -> QA: факты и ссылки
QA -> Публикация: черновик и просмотр
Публикация -> WordPress: draft
Публикация -> Свой сайт: custom adapter
WordPress -> Мониторинг: живой URL
Свой сайт -> Мониторинг: живой URL
```

Каждый этап пишет артефакт со статусом. `not_checked` означает отсутствие проверки, а не нулевой результат.

## 18 агентов: роль и доступ {span=2}

Каждого агента можно запустить отдельно. У роли есть вход, выход и статус `ready`, `needs_input` либо `failed`. Оркестратор соединяет результаты в `article-package.json`.

| Агент | Зачем и что отдаёт | Вход и доступ |
|---|---|---|
| Технический аудитор | Находит измеренные HTTP/HTML ошибки; JSON с URL и доказательством. | Публичный сайт. Токен не нужен. Панели остаются `not_checked`. |
| Технический исправитель | Готовит маленький diff по находке и повторяет проверку. | Отчёт аудитора и исходный код. Для выкладки нужны права на релиз и отдельное решение владельца. |
| Сборщик данных владельца | Снимает ограниченный срез Метрики, Вебмастера и GSC. | Сайт и даты; ID и read-only OAuth-токен только доступных панелей. Остальные — `not_checked`. |
| Сборщик Wordstat | Возвращает фразы и частотности с регионом и датой. | Исходные фразы, регион, folder ID и ключ Yandex Cloud. |
| Стратег запросов | Собирает кластеры, интент и соответствие страницам. | Реальная выгрузка спроса и бизнес-цель. Новый токен не нужен. |
| Досье исследования | Проверяет факты и свежие источники с URL. | Тема и доступный веб-поиск. Exa-ключ нужен только для этого дополнительного канала. |
| Бриф бренда | Фиксирует продукт, аудиторию, доказательства и запреты. | Материалы владельца. Новый API-токен не нужен. |
| Планировщик статьи | Делает план, структуру, объём и места полезных блоков. | Кластеры, интент, досье и бренд-бриф. Новый токен не нужен. |
| Редактор внутренних ссылок | Выбирает существующие страницы и анкоры без битых URL. | Карта сайта или обход. Публичному сайту токен не нужен. |
| Проверяющий обратные ссылки | Оценивает экспорт ссылок и риски; без экспорта пишет `not_checked`. | Файл владельца или read-only доступ к Вебмастеру/GSC. Ссылки не покупает. |
| Автор статьи | Пишет проверяемый черновик по плану. | Бриф, источники, структура. Нужен доступ к выбранному агенту/модели. |
| Автор изображений | Делает обложку и иллюстрации внутри текста, пишет alt и происхождение. | Бриф и место вставки. Встроенный Codex Image доступен в Codex; запись на сайт делает publisher. |
| Генератор метаданных | Готовит title, description, slug и данные для OG. | Готовый текст и обложка. Новый токен не нужен. |
| Редакционный аудитор | Проверяет факты, интент, ссылки, медиа и структуру; даёт `pass` либо находки. | Полный пакет и черновик. Новый токен не нужен. |
| Издатель WordPress | Загружает featured image и создаёт draft с read-back. Inline-медиа пока требует отдельной интеграции. | HTTPS WordPress, отдельный пользователь и Application Password с правами на статьи и медиа. |
| Издатель собственного сайта | Создаёт draft, проверяет preview и публикует точную запись. | Адаптер сайта, доступ к релизу/хранилищу, план отката. Права выдаёт владелец. |
| Монитор после выпуска | Сравнивает URL-уровень: индексацию, показы, клики, трафик и цели. | Живой URL, период, read-only GSC/Вебмастер/Метрика. |
| Оркестратор | Запускает роли по порядку и останавливает выпуск на невыполненных воротах. | Сайт, регион, цель и выбранный адаптер. Использует доступы только нужных ролей. |

Свой текст можно передать автору как вход. Проверка фактов, медиа и публикационные ворота остаются.

## Где получить доступы {span=2}

| Доступ | Кто выдаёт и как | Роль и проверка |
|---|---|---|
| Код сайта | Для технических исправлений нужен доступ к исходному коду и отдельной ветке изменений. | Чтение для аудита; запись только при согласованном исправлении. |
| Wordstat Cloud | Владелец создаёт Yandex Cloud folder и сервисный аккаунт с правом Search API; передаёт folder ID и путь к ключу вне Git. | Сборщик Wordstat делает один живой запрос по фразе и региону. |
| Яндекс Метрика | Владелец добавляет пользователя к точному счётчику; OAuth-приложение получает `metrika:read`. | Сборщик данных сверяет домен счётчика и читает ограниченный отчёт. |
| Яндекс Вебмастер | Владелец подтверждает хост и выдаёт OAuth-доступ к нему. | Сборщик данных и монитор сверяют точный хост; недоступность — `not_checked`. |
| Google Search Console | Владелец добавляет пользователя к точному свойству; OAuth scope `webmasters.readonly`. | Сборщик данных сверяет свойство перед запросом searchAnalytics. |
| Дополнительный поиск | Владелец выдаёт Exa-ключ, если нужен этот канал. | Досье сохраняет URL и дату ответа; обычный веб-поиск остаётся альтернативой. |
| Codex Image | Доступ к встроенному генератору в рабочем Codex. Клиентский API-ключ не передаётся в пакет статьи. | Автор изображений сохраняет файл, prompt, alt, размер и происхождение. |
| WordPress draft | Владелец создаёт отдельного пользователя и Application Password по HTTPS с правом статей и медиа. | Издатель создаёт draft, затем читает его обратно и открывает preview. |
| Собственный сайт | Владелец выдаёт доступ к чистому release-worktree и способу отката. | Издатель проверяет health, точный SHA, draft и живой URL. |

Секреты хранятся в окружении или защищённом хранилище. Для подключения указывают ID счётчика, свойство и путь к ключу; значения токенов не передают в чат или статью.

## Два пути публикации

| Шаг | WordPress | Собственный сайт |
|---|---|---|
| Основа | Шаблон Next.js + headless WordPress | Адаптер собственного сайта |
| Первая запись | WordPress draft | `createDraft` в хранилище сайта |
| Проверка | REST read-back и preview | read-back и тот же рендер сайта |
| Публикация | отдельное решение после просмотра | отдельный `publish` точной записи |
| Откат | CMS revision | точечная запись и release rollback |

WordPress-блок включает страницы блога, REST-клиент, sitemap/robots, preflight и создание черновика. Для установки в Next.js App Router есть отдельный [шаблон seo-blog-starter](https://github.com/ilyachu/seo-blog-starter). Перед публикацией проверьте черновик и предпросмотр на подключённом сайте.

## Изображение или GIF

Для обложки предусмотрен SVG-шаблон. Внутреннюю иллюстрацию Codex Image вставляют возле текста, который она поясняет. Пакет хранит файл, `src`, alt, подпись, размеры, SHA-256 и место блока. Предпросмотр и живой URL проверяются отдельно.

GIF выбирают, когда движение объясняет действие; для него нужны бюджет веса и статичный вариант при reduced motion. Статус медиа не становится `live_passed` до проверки опубликованной страницы.

## Как проверить результат {span=2}

| Этап | Доказательство |
|---|---|
| Данные | Точный сайт, регион, счётчик/свойство, дата ответа и статус каждого источника. |
| Черновик | Draft ID, read-back заголовка/тела/медиа и фактический preview на desktop/mobile. |
| Публикация | Живой URL, HTTP, canonical, robots, sitemap, OG, изображения и путь отката. |
| После выпуска | Page-level индексация, показы, клики, трафик и цели в наступившие периоды. |

Артефакты конкретного сайта сохраняются вне универсального Git. Код и локальные тесты не подтверждают доступ к панели или успешную публикацию.

## Что ещё измерять

- Индексация и позиции не подтверждаются в день публикации.
- Для каждого сайта заново проверяйте доступ к GSC, Вебмастеру и Метрике.
- Заявки нельзя приписывать статье без связи page-level входа с целью.
- Следующие окна: около 7 дней для индексации и 28 дней для трафика конкретной страницы.

## Как начать

1. Укажите сайт, регион, аудиторию и цель публикации.
2. Подключите только те панели и источники данных, к которым есть доступ.
3. Запустите один skill или `$seo-pipeline-orchestrator` в Codex. Для Claude Code используйте `/seo-pipeline-orchestrator`.
4. Сохраните `article-package.json`, preview, live URL и повторный замер.

Если данных или прав пока нет, агент отмечает соответствующий этап как `not_checked` и объясняет причину.

Отдельный запуск: «Используй `seo-technical-auditor` для моего URL. Верни измеренные находки и явно перечисли панели, к которым доступа нет».

Полный запуск: «Используй `seo-pipeline-orchestrator`. Сайт, регион и цель ниже. Выбери `wordpress` или `custom-site`, запиши реальные данные по каждому этапу, покажи draft и preview, затем попроси решение по публикации конкретной записи».
