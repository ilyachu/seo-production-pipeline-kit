# Готовность универсального SEO-конвейера

Этот файл описывает возможности текущего кода. Он не утверждает, что доступ к панелям или публикация на выбранном сайте уже проверены. Для каждого проекта сохраняйте отдельный `runs/<site>/` вне Git и повышайте статус только по фактическому ответу.

| Часть | Готовность кода | Проверка на выбранном сайте |
|---|---|---|
| 18 skills и оркестратор | Структура и ссылки проверяются `scripts/validate_skills.py`. | Задать бриф, проверить вход/выход каждой нужной роли и ворота конвейера. |
| Технический аудитор | Ограниченный HTTPS/HTML crawler и офлайн-тесты. | Обойти согласованный URL-набор, записать усечение и панельные `not_checked`; повторить каждый исправленный дефект. |
| Wordstat | Cloud-клиент и ручной CSV-фолбэк. | Указать фразу, регион, цель, folder ID и ключ либо CSV; сохранить дату и тип частотности. |
| Метрика, Вебмастер, GSC | Read-only сборщик с отдельным статусом каждого источника. | Получить доступ к точному счётчику/свойству; сверить права, период и числовой ответ. |
| Исследование, интент, текст и QA | Отдельные роли и контракт артефактов. | Проверить источники фактов, целевую страницу, ссылки, текст и решение редактора. |
| Обложка и inline-медиа | Локальный SVG-рендерер и инструкция для встроенного Codex Image. | Проверить файл, alt, происхождение, MIME, вес, desktop/mobile и живой URL. GIF требует статичный вариант при reduced motion. |
| WordPress | Отдельный Next.js App Router/headless WordPress шаблон и draft-only REST-скрипт; локальные тесты. | Внедрить в код сайта, создать тестовый draft и медиа, прочитать поля обратно, открыть preview и проверить SEO HTML. |
| Собственный сайт | Контракт `createDraft` → `readBack` → `publish` → `rollback`. | Реализовать адаптер сайта, проверить чистый релиз, backup, одну запись и живой URL. |
| Мониторинг | Роли и [план окон](POST_PUBLICATION_MONITORING.md). | Получить page-level индексацию, показы, клики, трафик и цели в наступившие периоды. |

## Открытые задачи

1. При необходимости добавить отдельное безопасное перечисление доступных счётчиков и свойств. Сейчас идентификаторы панелей необязательны: доступный источник отвечает, а неподключённый получает `not_checked`. OAuth-токены владелец обновляет вне CLI.
2. На тестовом WordPress проверить загрузку featured и inline-медиа, полный read-back, SEO-поля и безопасный повтор после timeout.
3. Расширить технический аудит structured data и скоростью через отдельный адаптер. Публичный crawler не изображает панельный отчёт.
4. Провести чистый запуск на разрешённом тестовом сайте. Сохранить вывод и ошибки вне универсального Git.
5. Добавлять GIF только для конкретного полезного движения, при поддержке reduced motion и согласованном бюджете веса.

Успешный локальный тест подтверждает код и контракт. Статус `ready` требует живого ответа источника или выбранного сайта.
