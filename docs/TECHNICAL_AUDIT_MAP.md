# Карта технического SEO-аудита

Цель: сохранить пункты старого аудит-бота и превратить их в воспроизводимые проверки. Каждый пункт имеет отдельный статус `pass`, `fail` или `not_checked`. Общий балл запрещён, если обязательные данные отсутствуют.

## Разделение работы

- `seo-technical-auditor`: публичный сайт без токенов, ограниченный обход и HTML/HTTP evidence.
- `seo-owner-data-collector`: Метрика, Вебмастер и GSC после подтверждения доступа к конкретному свойству.
- `seo-wordstat-collector`: отдельный источник частотности с явным регионом и датой.
- `seo-technical-fixer`: приоритизация дефекта, точный diff и повтор исходного замера после изменения. Он не принимает скриншот исходника за результат на проде.

## Пробелы старого бота

У прежнего `seo_leadgen` граф ссылок был неполным, а лимит страниц не ограничивал объём результата строго. Переносимый `technical_audit.py` хранит источник внутренней 404 и признак усечения обхода. `agency-growth-audit-ai` содержит отдельные модули обхода, технического SEO и Lighthouse, но их применимость проверяется по коду и тестам. `seo_ya/tools/bin/seo-audit.sh` после сбоя API мог записать `[]` и продолжить. Новый контракт сохраняет сбой отдельным статусом. Наличие шаблона отчёта не подтверждает доступ к панелям клиента.

## Минимальный прогон на новом сайте

1. Обойти ограниченную выборку публичных страниц и сохранить JSON в `runs/` вне Git.
2. Отдельно проверить целевую страницу, `/robots.txt`, `/sitemap.xml` и RSS, если он есть.
3. Записать текущую индексируемость, canonical и источники данных без догадок.
4. После изменения повторить тот же набор URL и сравнить статус каждого пункта.
