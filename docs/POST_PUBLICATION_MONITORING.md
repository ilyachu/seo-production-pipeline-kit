# Наблюдение после публикации

Для каждого сайта записывайте точный URL, дату выпуска, версию кода/данных, период до публикации, цель и панельные свойства. Файлы с реальными метриками остаются в каталоге клиента вне Git. Новая статья не получает историю показов в момент выпуска.

| Окно | Проверка | Доказательство |
|---|---|---|
| Сразу после выпуска | HTTP, canonical, robots, sitemap, OG, изображения, desktop/mobile, черновики и откат | Живые ответы с датой, точным URL и SHA/ревизией |
| Примерно через 7 дней | Обнаружение и индексирование URL, ошибки обхода, выбранный поисковой системой canonical | Статус точного свойства GSC/Вебмастера; отсутствие доступа — `not_checked` |
| Примерно через 28 дней | Показы, клики, CTR и запросы этой страницы; органические входы и согласованные цели | Выгрузка по точному URL и сопоставимым периодам; общий трафик сайта не приписывается статье |
| Ежемесячно | Ссылки на страницу, битые источники, актуальность фактов и ссылочный профиль | Повторный обход, доступный экспорт панели, список правок и повторная проверка |

Перед первым сравнением проверьте фильтр органики, атрибуцию целей и связь события заявки с URL статьи. Нулевой ответ и недоступный API — разные состояния. Причинный эффект записывайте только при достаточном page-level evidence.
