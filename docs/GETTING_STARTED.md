# Руководство по запуску SEO-конвейера

Репозиторий подходит для отдельной задачи и полного прогона. В нём есть искусственные примеры и шаблоны двух способов публикации. Данные, адреса и отчёты выбранного сайта остаются в его рабочем каталоге вне Git. WordPress и собственный сайт требуют отдельной проверки перед утверждением результата.

## 1. Получите репозиторий и проверьте основу

После получения доступа к репозиторию выполните:

```bash
python3 scripts/validate_skills.py
python3 -m unittest discover -s tests -q
node integrations/wordpress-next/scripts/validate-template.mjs
node --test integrations/wordpress-next/tests/*.test.mjs
```

Изучите [mini-PRD](../MINI_PRD.md), [архитектуру](../ARCHITECTURE.md), [источники](../SOURCE_INVENTORY.md) и [контракт пакета](../contracts/pipeline.md). Тесты подтверждают код и форматы, а не доступ к данным выбранного сайта.

## 2. Задайте контекст запуска

Запишите сайт, регион, аудиторию, продукт/услугу, бизнес-цель, целевое действие, CMS, владельца данных и запретные темы. Для Яндекс/Google нужны права к **точному** счётчику или свойству. Инструкция по выдаче доступов — [CREDENTIALS.md](../CREDENTIALS.md). Токены не отправляйте в чат и не кладите в Git.

## 3. Запускайте агента отдельно

Пример технической проверки:

```bash
python3 tools/technical_audit.py --site https://example.com/ --max-pages 30 --output runs/example/technical-audit.json
```

Пример задания Codex: «Используй `$seo-technical-auditor`. Прочитай `runs/example/technical-audit.json`. Верни URL, доказательство, приоритет и способ повторной проверки. Не называй это полным аудитом, если панели и скорость не проверены».

Для панелей запустите `$seo-owner-data-collector` с сайтом и периодом. ID счётчика и точное свойство GSC передайте для тех панелей, к которым есть доступ. Его CLI `tools/owner_data.py` читает токены только из окружения. Сверьте статусы трёх источников в JSON по `contracts/owner-data.schema.json`; отсутствие идентификатора или токена даёт `not_checked` только этому источнику, а не нулевой трафик.

Пример отдельной редакционной задачи: «Используй `$seo-keyword-strategist`. Возьми выгрузку Wordstat для региона, бизнес-цель и URL сайта. Раздели запросы по интенту и целевой странице. Не выдумывай частоты».

Для Claude Code используйте `/seo-technical-auditor` и `/seo-keyword-strategist`. Установка skills в пользовательский каталог необязательна; если нужна, сначала выполните `./scripts/install.sh --target codex --dry-run` или `./scripts/install.sh --target claude --dry-run`.

## 4. Запускайте всю цепочку

Попросите `$seo-pipeline-orchestrator` начать с публичного технического baseline, затем подключить доступные данные владельца, спрос, интенты, источники фактов, план, текст, перелинковку, обложку, мета и редакционный аудит. Он ведёт один `article-package.json`. `needs_input` для недоступной панели не блокирует независимые шаги; критичный технический блокер и провал аудита текста блокируют публикацию. Пользователь может передать свой текст; генератор тогда пропускается, а проверка фактов и публикационные ворота остаются.

Выберите один способ записи:

- [WordPress + Next.js](../integrations/wordpress-next/README.md): установить шаблон в целевой сайт, пройти public preflight и создать только draft через Application Password.
- [Собственный сайт](../integrations/custom-site/README.md): внедрить четыре операции `createDraft`, `readBack`, `publish`, `rollback` в репозитории сайта. Формат данных и способ релиза задаёт владелец сайта.

До публикации откройте реальный preview на desktop и mobile, проверьте источники, обложку, ссылки, title, canonical и rollback. После публикации проверьте живой URL, robots, sitemap, RSS/OG и зафиксируйте точную ревизию. Для проверки структуры используйте [искусственный пакет](../examples/article-package.example.json). Заполненный пакет сайта не коммитьте в общий репозиторий.

## 5. После выпуска

Следуйте [плану замеров](POST_PUBLICATION_MONITORING.md). `ready` означает проверенный артефакт текущего этапа; он не означает, что поисковик уже проиндексировал страницу, что позиции выросли или что заявка вызвана статьёй. При отсутствии доступа укажите `not_checked` и причину.
