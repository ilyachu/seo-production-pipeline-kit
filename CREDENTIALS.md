# Доступы для нового сайта

Начните с сайта, региона, бизнес-цели и выбранного способа публикации. Каждый агент спрашивает только нужные ему входы. Секреты держите в secret manager или локальном окружении вне Git. В prompt, argv, отчёт и репозиторий передавайте имена переменных и идентификаторы свойств, но не значения токенов.

| Источник и агент | Что владелец выдаёт | Как проверить |
|---|---|---|
| Wordstat → `seo-wordstat-collector` | Фраза, регион и цель. Для Cloud: folder ID, сервисный аккаунт с правом Search API и путь к авторизованному ключу. [Подробная настройка](skills/seo-wordstat-collector/references/setup.md). | `wordstat_client.py doctor`, затем один `top`. Если Cloud-доступа нет, принять ручной CSV и пометить `source=manual`; частотность не выдумывать. |
| Яндекс Метрика → `seo-owner-data-collector` | Доступ к точному счётчику и OAuth-токен приложения с `metrika:read`, только в `YANDEX_METRIKA_TOKEN`. [Официальная авторизация](https://yandex.ru/dev/metrika/ru/intro/authorization). | Указать `--metrika-counter`. Сверить ID и хост счётчика до запроса статистики. Отсутствие ID/токена — `not_checked` только для Метрики. |
| Яндекс Вебмастер → `seo-owner-data-collector` | Подтверждённый хост и OAuth-токен с доступом к информации о нём, только в `YANDEX_WEBMASTER_TOKEN`. [Официальная авторизация](https://www.yandex.ru/dev/webmaster/doc/ru/tasks/how-to-get-oauth). | Сначала получить пользователя и список доступных хостов, затем читать данные только точного HTTPS-хоста. Нет доступа — `not_checked`. |
| Google Search Console → `seo-owner-data-collector` | OAuth-приложение в Google Cloud, включённый Search Console API, scope `webmasters.readonly`, доступ пользователя к точному свойству; свежий access token в `GSC_ACCESS_TOKEN`. [Официальная инструкция](https://developers.google.com/webmaster-tools/v1/how-tos/authorizing). | Указать `--gsc-property`. Сверить строку свойства в списке до `searchAnalytics`. API key не заменяет OAuth для приватных данных. Нет свойства/токена — `not_checked` только для GSC. |
| Исследование → `seo-research-dossier` | URL источников и доступный веб-поиск. Exa и другие провайдеры возможны, если среда агента уже даёт инструмент и владелец выдал его ключ. | Сохранить точный URL и дату ответа. В этом репозитории нет собственного Exa API-клиента; при отсутствии инструмента используйте доступный веб-поиск или `blocked`. |
| WordPress → `seo-wordpress-publisher` | HTTPS URL CMS, отдельный пользователь с правами редактировать статьи и загружать медиа, Application Password в server-only окружении. [Порядок WordPress](integrations/wordpress-next/docs/credentials.md). | Public/auth preflight, затем один draft и read-back. Установленный пароль не выводить; запись `publish` требует отдельного решения. |
| Собственный сайт → `seo-custom-site-publisher` | Доступ к коду, конкретному адаптеру и резервной копии данных. Способ авторизации и права записи описывает владелец сайта в отдельном runbook. | Проверить текущую ревизию, draft, read-back, preview, точный URL и откат. Без адаптера статус `needs_input`. |
| Codex Image → `seo-image-producer` | Доступ к встроенному генератору в рабочем Codex. Клиентский API-ключ в пакет статьи не кладут. | Сохранить файл, prompt, alt, размеры, происхождение и визуальную проверку. В другой среде агент спрашивает доступный генератор. |
| PageSpeed и SERP | Публичный URL и выбранный инструмент. Технический crawler этого репозитория сам не вызывает PSI или платный SERP API. | Провести отдельный запрос с датой и ограничениями или записать `not_checked`. |

## Как получить и обновить OAuth-доступ

1. Владелец подтверждает сайт в нужной панели и выдаёт отдельному аккаунту минимальные права к точному счётчику/свойству.
2. Для Метрики и Вебмастера зарегистрируйте приложение Яндекс OAuth с нужными read-only правами. Для GSC зарегистрируйте OAuth-приложение Google и запросите `webmasters.readonly`. Следуйте связанным выше официальным инструкциям.
3. Выпустите access token в аккаунте с предоставленным доступом. Передайте его в secret manager и экспортируйте в окружение процесса под указанным именем. CLI не принимает токен в аргументах.
4. При `401/403` проверьте срок действия токена, приложение/scope, аккаунт и доступ к точному свойству. Обновите токен через поток OAuth поставщика; `tools/owner_data.py` не хранит refresh token и не обновляет access token автоматически.
5. Запустите минимальный read-only запрос. Сохраните дату, property ID и статус источника; значения токена и сырые клиентские данные остаются вне Git.

Для Wordstat ключ сервисного аккаунта и folder ID также остаются вне Git. [Агент Wordstat](skills/seo-wordstat-collector/SKILL.md) обязан спросить отсутствующие регион, цель и доступ, а затем предложить CSV-фолбэк. Панельные источники независимы: отсутствие GSC не блокирует Метрику или Вебмастер.
