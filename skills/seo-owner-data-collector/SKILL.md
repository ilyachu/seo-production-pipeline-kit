# SEO Owner Data Collector

Запускай `tools/owner_data.py`. Команда читает три панели и пишет один JSON. Wordstat сюда не входит: частотность собирает `seo-wordstat-collector`. Нет живого ответа — в отчёте `not_checked` или `failed`, не выдуманный ноль.

## Когда использовать

- Нужен период органики и целей Метрики по конкретному счётчику сайта.
- Нужна текущая сводка и диагностика хоста в Вебмастере, если API доступен.
- Нужна ограниченная выборка searchAnalytics точного свойства Search Console.
- Конвейер заполняет `sources` и не должен подставлять индекс, клики или заявки.

## Вход

- `--site`: абсолютный `https://` URL без логина, пароля, localhost и частного адреса.
- `--date1` и `--date2`: даты `YYYY-MM-DD`, конец не раньше начала. Один период для всех панелей.
- `--metrika-counter`: десятичный ID счётчика, если собирается Метрика. Сайт счётчика обязан совпасть с хостом `--site`.
- `--gsc-property`: точная строка свойства, `sc-domain:host` или origin URL, если собирается GSC. Совпадение посимвольное.
- `--output`: путь JSON. Для прогона клади файл в `runs/` и не коммить сырой отчёт.

Токены только в окружении, не в аргументах и не в файле:

- `YANDEX_METRIKA_TOKEN`
- `YANDEX_WEBMASTER_TOKEN`
- `GSC_ACCESS_TOKEN`

Пустая переменная значит доступа нет. Значение нельзя печатать, класть в argv, отчёт, лог или Git.

## Что делать

Из корня репозитория:

```bash
python3 tools/owner_data.py \
  --site https://example.com/ \
  --date1 2026-01-01 \
  --date2 2026-01-31 \
  --metrika-counter 12345678 \
  --gsc-property 'sc-domain:example.com' \
  --output runs/owner-data.json
```

Примерные ID и даты выше замените данными клиента. Если доступно только одно свойство, опустите флаг другого: его источник получит `not_checked`, а доступные источники продолжат сбор. Порядок каждого источника: сначала сверка, потом приватный отчёт.

- Метрика: `GET /management/v1/counter/{id}`. Если хост счётчика не равен хосту `--site`, статистика и цели не запрашиваются. После сверки — органика `ym:s:visits` и `ym:s:users` с фильтром `ym:s:trafficSource=='organic'`, не больше 10 поисковых систем, и до 20 целей с органическими достижениями.
- Вебмастер: пользователь и список хостов. Диагностика и сводка запрашиваются только для https-хоста, который совпал с сайтом. Сводка — текущее состояние, не история периода. Если API не отвечает, источник `failed`.
- Search Console: `GET /webmasters/v3/sites`, затем `searchAnalytics/query` только для точного `--gsc-property`. Сначала итог без разреза, затем не больше 25 запросов `searchType=web`.

Коды процесса: `0` файл записан и статус отчёта `ready` или `needs_input`; `4` файл записан и хотя бы один источник `failed`; `2` отвергнуты аргументы; `1` файл не записан. Код `4` нельзя описывать как нулевой трафик.

## Выход

Файл по `--output`. Контракт: `contracts/owner-data.schema.json`. В конвейере это снимок данных владельца, не статья и не аудит обхода.

У отчёта есть `agent` = `owner_data`, `schema_version` = `1`, `status`, `checked_at`, `inputs`. У каждого из трёх источников есть `source`, `property`, `period`, `checked_at`, `status`, `reason`, `quota`, `counts`, `data`.

- `ready`: сверка прошла и отчёт API разобран. `counts` хранит числа из ответа. Пустой законный ответ GSC помечен `data.empty=true`.
- `not_checked`: нет ID свойства, токена, API отказал в доступе, или счётчик/хост/свойство не совпали. `counts` и `data` равны `null`. Приватный отчёт не запрашивался.
- `failed`: сеть, HTTP-ошибка или ответ без обязательных чисел. `counts` и `data` равны `null`. Ноль вместо сбоя не записывается.

`quota` остаётся `null`, пока панель не отдала отдельное поле квоты. `sampled=true` у Метрики не округляется до полного периода. Обрезанные списки помечены `truncated`.

## Самостоятельный режим

Если нет сайта или дат, спроси их и остановись со статусом `needs_input`. Если отсутствует ID счётчика или точное свойство GSC, спроси их только для соответствующей панели и объясни, как получить доступ по [CREDENTIALS.md](../../CREDENTIALS.md). Запусти остальные доступные панели без пустых флагов. Если код `0`, верни путь, статус каждого источника, `counts` и причины `not_checked`. Код `4` или `1` означает ошибку; верни её текст без токена. Не заменяй пропущенную панель оценкой или нулём.

## Режим конвейера

Пиши только свой JSON. В `article-package.json` заполни `sources[]` для `yandex_metrika`, `yandex_webmaster` и `gsc`: статус, причина или путь к артефакту, `checked_at`. Wordstat не помечай собранным этой командой. Не заполняй `semantic`, `research`, `draft`, `meta`, `audit` и `publication`.

`ready` роли значит, что файл прочитан и ни один источник не `failed`. Источник `not_checked` оставляет роль в `needs_input`; сохраняй причину и продолжай независимые шаги конвейера. `failed` требует разбора ошибки источника, но не превращает доступные данные других панелей в нули. Чужие артефакты не меняй. Частотность, индекс, клики и заявки берутся только из записанных `counts`.

## Проверка

- В JSON есть три источника, у каждого `property`, `period`, `checked_at`, `status` и `counts`.
- При отсутствии ID/токена или несовпадении свойства статус `not_checked`, а URL приватного отчёта этого источника не вызывался.
- Ответ 5xx, обрыв сети и неразобранный JSON дают `failed`, `counts=null` и ненулевой код. В причине нет нулевых визитов.
- В stdout, stderr, argv и JSON нет значений `YANDEX_METRIKA_TOKEN`, `YANDEX_WEBMASTER_TOKEN` и `GSC_ACCESS_TOKEN`.
- Команда не пишет ничего, кроме `--output`, и не меняет прод.
