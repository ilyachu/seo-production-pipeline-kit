# SEO Image Producer

Изображение должно объяснять тему или усиливать бренд. Отдельно решай задачу обложки и каждого изображения внутри текста. Запиши, какой путь использован и где блок стоит в статье.

Локальный путь не ходит в сеть и не читает учётные данные. Это [tools/render_svg_cover.py](../../tools/render_svg_cover.py): детерминированный SVG 1600×900, только стандартная библиотека Python. Идея макета — тёплый редакционный постер с крупной типографикой. Бренд и текст берутся только из брифа нового запуска. Искусственный пример: [examples/cover-demo.svg](../../examples/cover-demo.svg).

```bash
python3 tools/render_svg_cover.py \
  --title "Заголовок статьи" \
  --subtitle "Один тезис" \
  --site-name "Издание" \
  --accent "#8C3D2F" \
  --output output/cover.svg
```

Второй путь — встроенный Codex Image (`image_gen`) для статичной растровой иллюстрации. Для самой генерации отдельный API-ключ клиента не нужен в доступном Codex. Если инструмента нет в среде другого агента, пометь генерацию `needs_input`, а не подменяй её фиктивным файлом. Попроси модель оставить место для кропа и не изображать настоящие клиентские метрики. Сохрани полученный файл в репозитории или защищённом каталоге проекта: путь к временному output генератора не годится для публикации.

GIF — отдельный вход, который владелец передал с правами на использование, либо результат специализированного инструмента анимации. Встроенный Codex Image создаёт статичный кадр; один PNG не называй GIF. Анимация нужна, только когда показывает действие, которое трудно объяснить одним кадром. Для GIF требуется статичный кадр или другой вариант при `prefers-reduced-motion`. Если шаблон сайта не умеет переключать медиа, выбери статичное изображение.

## Когда использовать

- Черновик и бренд-бриф готовы.
- Нужна hero/featured image или иллюстрация сложного блока внутри статьи.
- Нужна повторяемая обложка с живым заголовком на макете, без внешнего API.
- Нужно подготовить alt-текст и параметры для WordPress или своего сайта.

## Вход

- H1, подзаголовок или основной тезис, название издания, аудитория и тон бренда.
- Цвет акцента `#RRGGBB`, если он задан. Иначе локальный рендерер берёт `#8C3D2F`, подпись «Редакция» и холст 1600×900.
- Для рисованного пути: соотношение сторон, место текста и доступный инструмент изображения.
- Визуальный стиль сайта: фото или графика, степень реализма и нужна ли видимая подпись. Не выбирай стилизованную иллюстрацию, когда владелец просит фотографию.
- Для inline-медиа: после какого блока статьи оно стоит, какую мысль поясняет, разрешённый формат и бюджет веса. Для GIF также нужен смысл движения и статичный вариант.

## Что делать

1. Выбери один визуальный тезис. Не помещай всю статью в один коллаж.
2. Для типографической обложки запусти локальный рендерер. Заголовок на макете — аргумент `--title`, не просьба к модели нарисовать буквы.
3. Для растра сформируй prompt: назначение, сцена, объект, композиция, свет, палитра, ограничения. Если бриф просит фото, укажи фотореалистичную редакционную фотографию с естественными деталями. Не проси модель писать текст или изображать реальные метрики клиента.
4. Сохрани файл в проект. Alt возьми из `<title>` и поля `alt` в `<metadata>` SVG или напиши сам для растра: что на изображении и о какой статье оно. Не набивай alt запросами. Видимая подпись необязательна: не добавляй шаблонное «сгенерировано ИИ» или «иллюстрация», если владелец не просил. Происхождение и prompt сохрани в `media.origin`, а синтетические данные не выдавай за настоящие.
5. Prompt для повторения возьми из `<desc>` / `metadata.prompt` или из запроса к image-tool. Туда же origin: локальная редакционная обложка, не чужой бренд.
6. Не используй чужие логотипы и лица без разрешения. Не выдавай синтетическую сцену за документальный факт. Не подставляй ключи API.
7. Для изображения внутри текста вставь типизированный блок в черновик. Проверь исходный файл, реальные размеры, MIME, вес и SHA-256. После загрузки открой preview на desktop и mobile; после выпуска запроси URL файла и проверь `img src`, alt, подпись, lazy-load и отсутствие переполнения.
8. Для GIF дополнительно проверь первый кадр, смысл движения, размер и статичный вариант в режиме reduced motion. Без этих проверок GIF остаётся `not_checked` и в публикацию не идёт.
9. Для серии фото зафиксируй style lock бренда: композицию, свет, палитру и обработку. Один и тот же стиль передавай во все кадры серии.
10. Проверь реальный размер файла и итоговый OG. Фактический размер должен совпадать с заявленным.
11. Если владелец просил без видимой подписи генерации, убедись, что на изображении нет водяного знака и подписи генератора.

## Выход

В `media` сохраняй обложку и `inline_assets[]`. Для каждого inline-файла: `kind`, `path`, `src`, `prompt`, `generator`, `width`, `height`, `bytes`, `sha256`, `alt`, `origin`, `placement_after_block`, `qa_status`; `caption` добавляй только если он помогает читателю. Для GIF добавь `motion_purpose` и `reduced_motion_fallback`. Путь и `src` должны вести к реальному сохранённому файлу. Не коммить клиентский файл без разрешения владельца.

Для локального SVG: `generator` = `local-editorial-svg`, `dimensions` = `1600x900`, `license_or_origin` указывает редакционную идею без переноса чужого бренда. `qa_status` = `not_checked`, пока обложку не открыли как картинку. После просмотра рендера — `passed` или конкретный дефект.

## Самостоятельный режим

Можно собрать обложку только по теме и стилю. Если издание, акцент или размер неизвестны, перечисли допущения рендерера и не перезаписывай существующий файл. Рисованный путь доступен отдельно, когда пользователь просит сгенерированное изображение.

## Режим конвейера

Используй `outline.page_goal`, H1 черновика и `brand`. Если в брифе нет своего изображения и не задан генератор, локальный SVG закрывает обложку. Для inline-рисунка выбери точное место возле относящегося текста. Не вызывай генератор молча поверх уже принятого файла. Передай `path`, `src` и `alt` publisher, а обложку — генератору метаданных. Публикацию этот skill не выполняет.

## Проверка

- Файл существует.
- Открой именно рендер (браузер или просмотрщик SVG), а не только строку prompt. На картинке проверь поля: длинный кириллический заголовок не вылезает за рамку, строки не наезжают друг на друга, акцент не заменяет собой текст.
- Кроп 1600×900 читается как обложка: бумага, рамка, подпись издания, заголовок, подзаголовок.
- XML открывается, символы `&`, `<`, `>` и кавычки экранированы, alt описывает обложку и статью, а не список ключей.
- В файле нет ссылок на внешние картинки, ключей и адресов API.
- `qa_status` соответствует этому просмотру. Успешная запись файла сама по себе просмотр не заменяет.
- Для inline-изображения порядок блоков соответствует плану статьи. URL отдаёт настоящий MIME и ненулевой файл. В обоих viewport изображение не обрезано и подпись читается.
- Для GIF статичный вариант отображается при reduced motion; если сайт этого не поддерживает, используй статичный кадр.
- Серия фото следует одному style lock бренда.
- Реальный размер файла и итоговый OG совпадают с заявленным.
- Нет видимой подписи генерации, если владелец так указал.
