# SEO Pipeline Orchestrator

Координируй роли, но не подменяй их одной большой генерацией. Установленная копия контракта: [pipeline.md](references/pipeline.md).

## Когда использовать

- Нужна статья под ключ: техника, спрос, факты, текст, изображение и один канал записи.
- Нужно продолжить незавершённый `article-package.json`.
- Нужно понять, на каком шаге и почему остановилась цепочка.
- Нужно выбрать WordPress draft или адаптер своего сайта, не смешивая их.

## Вход

- Сайт, тема, регион и бизнес-цель.
- Продукт, аудитория и целевое действие.
- Доступные источники: обход сайта, Wordstat/CSV, панели, бренд-материалы.
- Канал записи: `wordpress` или `custom-site`. Для своего сайта — имя реализации адаптера и способ получить права, без секретов.
- Желаемый результат: baseline, план, черновик текста, draft адаптера или полный пакет.

В начале составь короткий список нужных доступов по [CREDENTIALS.md](../../CREDENTIALS.md). Спроси у владельца регион, Wordstat folder ID и путь к ключу либо CSV; ID счётчика Метрики и точное свойство GSC только для подключаемых панелей; WordPress URL/права либо контракт своего сайта только перед записью. Значения OAuth-токенов, Application Password и приватного ключа в чат не проси. Отсутствующий источник помечай `not_checked` и продолжай независимые шаги.

## Порядок работы

1. Создай или прочитай `article-package.json` версии 1.0.
2. Сначала запусти `seo-technical-auditor` и запиши `technical`. Без `technical.status=ready` и файла отчёта семантику не начинай.
3. Запусти `seo-technical-fixer` по измеренным находкам. До контента допускаются только критичные блокеры: точный маленький diff и повторная проверка того же URL. Некритичные находки отложи. Без отдельного подтверждения diff не применяй и не деплой.
4. Запусти `seo-owner-data-collector` для Метрики, Вебмастера и Search Console. Для Wordstat, PageSpeed и SERP запиши отдельные `sources[]`. Нет живого ответа — `status=not_checked` и причина. Не подставляй частотность, индекс или скорость. Уважай запрет владельца на новый платный сбор: если он его запретил, не запускай платный источник. Используй переданные данные с датой и областью действия. Не переноси частотность на другую тему — тогда `not_checked`.
5. Дальше запускай skills в порядке контракта. После каждого шага фиксируй статус, артефакт и недостающие входы.
6. После семантики покажи ядро, хвосты, интент и температуру только из записанных запросов.
7. До письма зафиксируй досье, бренд-бриф, план и карту внутренних ссылок.
8. До финального черновика запусти `seo-backlink-reviewer`. Источник — экспорт Вебмастера, Search Console или переданный файл. Нет данных — `backlinks.status=not_checked` и причина. Ссылки не покупай.
9. После текста создай обложку и нужные иллюстрации внутри статьи через `seo-image-producer`. Для статичного рисунка можно использовать встроенный Codex Image; GIF требует полезного движения и статичного варианта при reduced motion. Запиши alt, происхождение, место вставки и QA каждого файла. Затем создай метаданные и запусти независимый `seo-content-auditor`.
10. При провале аудита верни только проблемные секции соответствующему skill. Запись в адаптер не начинай. Для партии страниц останавливай публикацию на первом блокере: не публикуй следующие элементы, пока блокер не закрыт.
11. При `audit.status=pass` выбери один адаптер. WordPress — только `seo-wordpress-publisher` и по умолчанию `status=draft`. Свой сайт — только `seo-custom-site-publisher`: `createDraft`, затем предпросмотр и `readBack`.
12. `publish` выполняй лишь после отдельного явного подтверждения конкретного draft ID. Затем проверь живой URL: HTTP, desktop/mobile, canonical, robots, sitemap, OG и каждое inline-медиа. План отката должен быть записан до этой записи.
13. После успешной живой проверки запусти `seo-post-publication-monitor`. Сравнивай запросы, трафик и конверсии этой страницы по окнам. Индексацию сразу не обещай. Без page-level evidence не записывай причинность.

## Выход

- Обновлённый `article-package.json` с `technical`, `technical.fixes`, `sources`, `backlinks`, одним `publication.adapter` и `monitoring`, если шаг уже доступен.
- Короткий журнал: шаг, результат, проверка, оставшийся риск.
- Ссылки и пути ко всем созданным артефактам. Секретов в журнале нет.

## Самостоятельный режим

Если часть ролей не установлена, выполни доступные шаги, пометь остальные `needs_input` и дай точную команду продолжения. Не изображай полный конвейер завершённым. Отсутствующий baseline не заменяется фразой, что техника проверена. Отсутствующий fixer не закрывает критичный блокер. Отсутствующий разбор ссылок не считается чистым профилем. Отсутствующий мониторинг не считается замером страницы.

## Режим конвейера

Передавай один пакет, не пересказывай данные между ролями вручную. Следующий шаг читает только утверждённые секции и не меняет исходные данные предыдущего шага без причины. `needs_input` и `failed` не считаются выполнением. Семантика и текст ждут закрытия критичных блокеров. Финальный черновик ждёт записанный `backlinks`. Publisher не запускается до `audit.status=pass`. Мониторинг запускается после живой проверки и не пишет в WordPress или custom-site.

## Проверка

- Семантика не начата раньше technical baseline со статусом `ready`.
- До контента исправлены только критичные блокеры; у каждого применённого есть повторная проверка того же URL. Некритичные находки не раздувают diff.
- Diff не задеплоен молча и не включает посторонние файлы.
- Разбор входящих ссылок записан до финального черновика. Нет экспорта — `not_checked` с причиной, без покупки ссылок.
- Каждый внешний источник имеет явный статус; `not_checked` содержит причину.
- Запрет владельца на новый платный сбор соблюдён; используются только переданные данные с датой и областью действия.
- Частотность не перенесена на другую тему; при неопределённости — `not_checked`.
- Для партии страниц публикация остановлена на первом блокере.
- Частотность, факты, индекс и успех публикации не выдуманы.
- Аудит `pass` выполнен до любой записи WordPress или custom-site.
- В пакете один адаптер. Черновик подтверждён read-back и предпросмотром.
- `publication.status=ready` только вместе с живым URL и проверками из контракта.
- Мониторинг идёт после живой проверки, сравнивает запросы, трафик и конверсии страницы и не объявляет причинность без evidence.
- В JSON, Markdown, логах и командной строке нет секретов.
- `publish` не выполняется без отдельного явного подтверждения.
