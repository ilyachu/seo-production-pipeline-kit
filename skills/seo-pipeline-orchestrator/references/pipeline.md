# Контракт конвейера

Все роли читают и дополняют один `article-package.json`. Неизвестное значение — `null`, статус `needs_input` или явный `not_checked` с непустой причиной. Модель не заполняет пробелы догадками и не считает непроверенный источник успешным.

## Порядок

1. `seo-technical-auditor` → `technical`. Это baseline HTTP/HTML целевого сайта до семантики.
2. `seo-technical-fixer` → `technical.fixes`. До контента чинятся только критичные блокеры публикации и индексации из измеренного отчёта. На каждый — точный маленький diff и повторная проверка того же URL. Некритичные находки откладываются. Diff не применяется молча и не разрастается на посторонние изменения.
3. `seo-owner-data-collector` → `sources[]` для Метрики, Вебмастера и Search Console. Сверь счётчик и точное свойство до приватного отчёта. У каждой записи есть `name` и `status`. Нет доступа — `not_checked` и причина, не выдуманная цифра. Wordstat собирается отдельно.
4. `seo-wordstat-collector` → `semantic.raw_queries`. Шаг начинается только после записанного technical baseline и закрытых критичных блокеров.
5. `seo-keyword-strategist` → `semantic.clusters`
6. `seo-research-dossier` → `research.claims`
7. `seo-brand-brief` → `brand`
8. `seo-outline-planner` → `outline`
9. `seo-linking-editor` → `links`. Это внутренние и исходящие ссылки статьи.
10. `seo-backlink-reviewer` → `backlinks`. До финального черновика. Только реальный экспорт Вебмастера, Search Console или переданный файл. Нет данных — `not_checked` и причина. Покупка и размещение ссылок не выполняются.
11. `seo-article-writer` → `draft`
12. `seo-image-producer` → `media`: отдельно обложка и 0–N изображений внутри текста. Встроенный Codex Image доступен для статичных иллюстраций. GIF допускается только при полезной анимации и наличии статичного варианта для reduced motion.
13. `seo-meta-generator` → `meta`
14. `seo-content-auditor` → `audit`. Это QA статьи до любой записи в CMS или свой сайт.
15. Ровно один адаптер записи, после `audit.status=pass`:
    - WordPress: `seo-wordpress-publisher` → `publication.adapter=wordpress`. По умолчанию только draft.
    - Свой сайт: `seo-custom-site-publisher` → `publication.adapter=custom-site` и `implementation`. Сначала `createDraft`, не publish.
16. После записи: предпросмотр и `readBack`. `publish` — отдельное явное подтверждение этого объекта. Затем проверка живого URL в `publication.live_checks` и записанный откат.
17. `seo-post-publication-monitor` → `monitoring`. Только после живой проверки URL. Сравнение запросов, трафика и конверсий этой страницы. Индексация не считается мгновенной. Причинный эффект без evidence не записывается.

WordPress draft и custom-site draft — разные адаптеры. Один прогон выбирает один. Успех одного не заполняет поля другого. Fixer и monitor не становятся третьим адаптером и ничего не публикуют.

## Ворота качества

- Нельзя собирать семантику, пока `technical.status` не `ready` и в `technical.artifact` нет отчёта обхода. `blocked`, пустой обход и `not_checked` по страницам не открывают семантика-шаг.
- Нельзя начинать семантику и текст, пока критичный блокер из `technical.fixes` не перепроверен на том же живом URL со статусом `pass`, либо пока явно записано, что измеренный отчёт таких блокеров не содержит. `medium` и `low` контент не блокируют и на этом шаге не исправляются.
- Правка блокера не выкатывается без отдельного подтверждения. Предложенный diff без повторного живого замера не закрывает ворота техники.
- Панели, которых baseline не вызывает, остаются в `technical.not_checked` или в `sources[]` со статусом `not_checked` и причиной. Это не провал сайта и не выполненная проверка.
- Нельзя классифицировать спрос без региона, бизнес-цели и исходных запросов. Недоступный Wordstat, Метрика, Вебмастер, Search Console или SERP получают `not_checked` либо `blocked` с причиной; частотность и позиции из них не выдумываются.
- Нельзя переносить внешний факт в текст без записи в `research.claims` и URL. Факт о собственном продукте должен иметь источник в `brand.product_truth` или `brand.proof`.
- Нельзя писать статью без утверждённых `brand`, `outline` и `links`.
- Нельзя запускать финальный `draft`, пока `seo-backlink-reviewer` не записал `backlinks` со статусом `ready` или `not_checked` и непустой причиной. Отсутствие выгрузки не изображается чистым профилем и не требует покупки ссылок.
- Нельзя помечать аудит как `pass`, если есть неподтверждённые факты, сломанная структура или обязательные поля `needs_input`.
- Для каждого inline-медиа запиши место вставки, src, alt, размеры, происхождение и QA. Перед записью проверь файл, MIME и вес; в preview — загрузку и мобильную ширину; после выпуска — HTTP и фактический `<img src>`. Для GIF дополнительно нужны смысл движения, ограничение веса и статичный вариант для reduced motion; если адаптер не умеет такой вариант, используй статичное изображение.
- Нельзя вызывать запись адаптера, пока аудит не `pass`. Preflight без записи это правило не нарушает.
- После `createDraft` или WordPress POST нельзя считать черновик созданным без `readBack` и предпросмотра. Сверка покрывает статус, slug и поля, которые адаптер обязан был сохранить.
- По умолчанию оба адаптера остаются в draft. `publish` — отдельное подтверждённое действие над конкретным draft ID.
- Нельзя ставить `publication.status=ready`, пока нет живого URL и проверок HTTP, рендера desktop/mobile, canonical, robots, sitemap и OG. Непроверенный пункт — `not_checked` с причиной, и тогда публикация не `ready`. План отката записан до publish.
- Нельзя запускать мониторинг, пока живой URL не проверен. Запросы, трафик и конверсии берутся на уровне этой страницы. Ненаступившее окно и панель без доступа — `not_checked`. Общий рост сайта не записывается как эффект статьи, пока нет сравнимого page-level evidence.

## Независимый режим

Любой skill может получить данные напрямую от пользователя. Он создаёт только свой раздел пакета и перечисляет `inputs_used`, `assumptions`, `missing_inputs` и `status` (`ready`, `needs_input`, `blocked` или `failed`). Такой результат совместим с конвейером, но не изображает отсутствующие предыдущие шаги как выполненные. Publisher не подменяет отсутствующий аудит статусом `pass` и не пишет во второй адаптер. Fixer без измеренной находки не делает вид, что URL уже исправлен. Reviewer без экспорта не ставит ссылкам качество. Monitor без живого URL не ставит замер выполненным.
