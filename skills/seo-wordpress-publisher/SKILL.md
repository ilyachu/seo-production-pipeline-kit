# SEO WordPress Publisher

Это skill с внешним изменением состояния. По умолчанию создавай только `status=draft`. Публичный `publish` возможен лишь после отдельного явного подтверждения человека.

## Когда использовать

- Аудит статьи завершён со статусом `pass`.
- WordPress доступен по HTTPS и подготовлена отдельная учётная запись с минимальными правами.
- Пользователь просит draft/preflight или явно подтверждает публикацию конкретного материала.

## Вход

- `draft`, `media`, `meta`, `audit` из пакета.
- `WORDPRESS_BASE_URL`, `WORDPRESS_USERNAME`, `WORDPRESS_APPLICATION_PASSWORD` из переменных окружения/секрет-хранилища.
- Категории, теги, author ID и маппинг SEO-плагина.

## Что делать

1. Preflight: HTTPS, `/wp-json/wp/v2`, аутентификация, права, категория/автор, отсутствие существующего slug.
2. Никогда не печатай пароль, Authorization header или сырой секрет в лог.
3. Загрузку медиа выполняй отдельно через `/wp/v2/media`; проверь MIME, размер, alt и полученный ID.
4. Создай `/wp/v2/posts` с `status=draft`, title, content, excerpt, slug, featured_media, categories/tags.
5. Прочитай созданный draft обратно и сравни поля.
6. Если нужны Yoast/Rank Math custom fields, сначала проверь, что они разрешены REST-конфигурацией; не считай их сохранёнными по HTTP 201 без чтения.
7. Для `publish` покажи URL/ID draft и запроси явное подтверждение именно этого объекта.

## Выход

В `publication`: `mode`, `post_id`, `status`, `edit_url`, `public_url`, `media_id`, `verified_fields`, `warnings`, `created_at`. Секретов там нет.

## Самостоятельный режим

Можно выполнить только preflight или создать draft из готового HTML. Без audit pass это явно помечается как операторское исключение; публичная публикация всё равно запрещена без подтверждения.

## Режим конвейера

Принимай пакет только после `audit.status=pass`. Ошибка API означает `failed`, а не «успех с предупреждением». Не повторяй POST вслепую: сначала проверь, не создался ли объект.

## Проверка

- Используется HTTPS и отдельный Application Password.
- Созданный объект прочитан обратно; status и slug совпадают.
- В логах/файлах нет секретов.
- `publish` не выполнен без отдельного явного подтверждения.
